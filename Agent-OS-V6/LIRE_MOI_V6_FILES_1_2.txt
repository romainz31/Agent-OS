AGENT-OS V6-Files 1.2 — Fichier existant : Renommer ou Écraser

INSTALLATION
V6-Files 1.1 Mission Control doit déjà être installé.
1. Arrête api_server.py avec Ctrl+C.
2. Décompresse ce ZIP dans Agent-OS-V6, avec le dossier payload.
3. Dans PowerShell ouvert dans Agent-OS-V6 :
   python .\APPLY_V6_FILES_1_2.py
4. Redémarre :
   python .\api_server.py
Aucune nouvelle dépendance à installer.

POUR TA MISSION M-005 DÉJÀ ÉCHOUÉE
Envoie dans Paul :
retry M-005

Si le fichier existe toujours, M-005 passe en attente de ton choix :
- fichiers renommer M-005 "nouveau_nom.txt"
- fichiers ecraser M-005

Le numéro de mission reste le même. Remplace le nom d’exemple par celui voulu.
Le nouveau nom doit être un simple nom de fichier, avec extension, dans le même
répertoire. Le contenu demandé initialement est conservé ; seul son nom/format change.
Le fichier déjà présent n’est pas renommé : il reste en place lorsqu’on choisit
un autre nom pour le nouveau fichier.

DANS MISSION CONTROL
La mission passe en Approbation, avec le chemin concerné et les deux possibilités.
Le texte indique explicitement que le bouton Autoriser signifie ÉCRASER ce fichier.
Pour un nouveau nom, utilise la commande « fichiers renommer ... » dans le chat.
Refuser conserve le fichier et refuse la création ; Annuler arrête la mission.

COMPORTEMENT
- Une création qui rencontre un fichier existant attend ton choix au lieu
  d’échouer immédiatement.
- Si le nouveau nom choisi existe aussi, la même mission te repose le choix.
- Le titre de la mission suit le nouveau nom.
- L’écrasement nécessite une autorisation explicite, à usage unique et valable
  15 minutes. Un simple « oui » n’est pas une autorisation d’écrasement.
- L’autorisation concerne la version du fichier observée lors de la demande.
  Si le fichier a changé avant la génération ou au contrôle précédant le
  remplacement, la mission redemande ton choix et ne remplace pas cette version.
- Le contenu est généré et validé avant le remplacement du fichier. Il est
  préparé dans un fichier temporaire du même répertoire, puis remplacé en une
  opération ; le temporaire est retiré après succès ou échec.
- Une erreur de génération, un refus ou une expiration conserve l’original.
- Un redémarrage annule les autorisations ; une relance redemande ton choix.
- Aucun accord d’écrasement n’est sauvegardé pour être réutilisé plus tard.

CONTENU DU PATCH
agentos/file_assistant.py et agentos/file_missions.py, fournis en entier.
L’installateur remplace ces deux modules et sauvegarde leurs versions précédentes
sous backups/V6-Files-1.2-... . Il ne modifie pas les fichiers de mémoire personnelle,
le runtime, l’interface Web, les dépendances ou les données existantes.
Le ZIP ne contient ni fichiers de test, ni données personnelles, ni projet complet.

VALIDATION
Scénarios API locaux, Ollama simulé et réseau désactivé :
- même mission M-xxx en attente du choix ;
- renommage vers un nom libre ou déjà utilisé ;
- refus et écrasement explicite via le chat et le bouton Web ;
- aucun écrasement implicite ni réutilisation d’un accord ;
- fichier changé avant ou pendant la génération ;
- expiration, annulation/relance et redémarrage ;
- original conservé tant qu’aucun remplacement valide n’a été autorisé.
Validation réalisée sous Linux. Le test sur ton serveur Windows reste à effectuer.
