AGENT-OS — V6-Files 1.0
Module fichiers indépendant des versions de mémoire V6.1 à V6.3

INSTALLATION
1. Arrête api_server.py avec Ctrl+C.
2. Décompresse ce ZIP dans ton dossier Agent-OS-V6 (celui contenant api_server.py).
   Garde le sous-dossier payload avec le script d’installation.
3. Depuis PowerShell ouvert dans Agent-OS-V6 :
   python .\APPLY_V6_FILES_1_0.py
4. Pour PDF, création Word/Excel et validation YAML :
   python -m pip install -r requirements-documents.txt
5. Redémarre :
   python .\api_server.py
6. Dans Paul (Web, CLI ou Telegram connecté au même serveur) :
   fichiers aide

Le ZIP contient uniquement ce nouveau module, ses dépendances optionnelles,
son installateur et cette notice. Il ne contient aucune donnée personnelle.
L’installateur ajoute huit lignes dans agentos/autonomous_runtime.py et copie
agentos/file_assistant.py + requirements-documents.txt. Il conserve les autres
changements présents et sauvegarde les fichiers remplacés sous backups.
Il ne touche pas à memory.py, personal_manager.py, conversation.py ni à leurs bases.
Si le point d’insertion a changé, il s’arrête avant toute modification.
Aucun pip install automatique ; aucun changement envoyé à GitHub.

Il conserve le chemin source, une empreinte SHA-256, la date d’analyse, l’extrait,

FORMATS
Création : TXT, MD, CSV, TSV, JSON, YAML/YML, HTML, CSS, JS, PY, XML, LOG, INI,
CFG ; DOCX, XLSX et PDF simples avec les dépendances optionnelles.
JSON et YAML sont validés avant écriture ; YAML nécessite PyYAML.
DOCX/PDF : mise en page simple. Le PDF utilise une police latine ; les glyphes
non compatibles provoquent une erreur, pas une substitution silencieuse.
XLSX : tableau de valeurs textuelles, pas de formules ni de macros.
Aucun programme généré n’est exécuté par ce module.
Lecture : formats texte ci-dessus, DOCX (corps et tableaux), PDF avec texte,
PNG/JPG/JPEG/WEBP avec modèle vision. Lecture XLSX/ancien DOC non incluse.
Un PDF scanné sans texte n’est pas interprété automatiquement : exporter ses
pages en images puis les analyser avec le modèle vision.

IMAGES — CONFIGURATION
Un modèle texte seul ne suffit pas pour examiner une image.
Installe/choisis un modèle vision compatible Ollama. Dans le PowerShell qui
lance api_server.py, avant le lancement, définis son nom EXACT :
$env:AGENTOS_VISION_MODEL="NOM_DU_MODELE_VISION_INSTALLE"
python .\api_server.py

Le module ne télécharge aucun modèle automatiquement. S’il manque, l’image est
signalée « non analysée » et les autres fichiers continuent à être traités.
Le contenu est envoyé à OLLAMA_HOST déjà configuré dans Agent-OS ; si ce serveur
est distant, les documents y sont transmis après ton accord affichant cet hôte.
Référence technique : https://docs.ollama.com/capabilities/vision

LIMITES ET CONTRÔLES
- 100 fichiers maximum par analyse, 10 Mio par fichier, 5000 entrées parcourues.
- Sans sous-dossiers par défaut ; ajoute « sous-dossiers » pour les inclure.
- Les noms commençant par un point sont ignorés lors du parcours de dossier.
- Liens symboliques, jonctions Windows et fichiers spéciaux refusés.
- 24000 caractères conservés par fichier ; PDF limité à 30 pages et au plafond
  de caractères. Une lecture tronquée est marquée partielle.
- Un traitement documentaire à la fois ; la conversation reste disponible.
- Les accès des anciens outils/agents ne deviennent pas un bac à sable système :
  les demandes gérées par ce nouveau circuit sont celles soumises à son accord.
- Ne modifie pas l’arborescence du dossier pendant une analyse/un classement.
