AGENT-OS V6-Files 1.1 — Missions natives et Mission Control

INSTALLATION (V6-Files 1.0 doit déjà fonctionner)
1. Arrête api_server.py avec Ctrl+C.
2. Décompresse ce ZIP dans le dossier Agent-OS-V6 qui contient api_server.py.
   Conserve le sous-dossier payload fourni avec l’installateur.
3. Dans PowerShell ouvert dans ce dossier :
   python .\APPLY_V6_FILES_1_1.py
4. Redémarre :
   python .\api_server.py
5. Actualise l’interface Web.
Aucune nouvelle dépendance à installer.

CE QUI CHANGE
- Les créations, analyses, classements et exports deviennent de vraies missions
  M-001, M-002, etc., dans la numérotation commune à toutes les missions.
- Titres explicites, par exemple : « Création de fichier — courses.txt ».
- Présence dans Mission Control, avec une tâche Documents liée à la mission,
  un état, une progression 0/1 puis 1/1 et le résultat dans le détail.
- Les demandes d’accès apparaissent dans le panneau des approbations existant :
  les boutons Autoriser et Refuser déclenchent le même contrôle que le chat.
- Pause, Reprendre, Annuler et Relancer utilisent le traitement documentaire.
  Pause/annulation s’appliquent aux points de contrôle : un calcul Ollama déjà
  en cours peut finir, puis le traitement s’arrête avant l’opération suivante.
  Les fichiers déjà créés sont conservés.
- Une relance demande une nouvelle autorisation ; elle ne réutilise pas
  l’autorisation précédente. Une autorisation expirée disparaît du panneau.
- Le traitement documentaire reste en arrière-plan dans son exécuteur dédié.
  Le superviseur des autres agents ne relance pas automatiquement ces tâches.
- Les anciens travaux F-... sont importés en missions M-... au démarrage,
  sans être exécutés à nouveau. Les anciens identifiants restent des alias
  pour consulter les résultats et les informations déjà extraites.
- Les travaux interrompus doivent être relancés avec un nouvel accord.
  Pour un ancien travail importé sans description structurée de l’action,
  renvoie la demande initiale afin de créer une nouvelle mission.

FICHIERS PROJET AJOUTÉS/MODIFIÉS
agentos/file_assistant.py : module complet mis à jour.
agentos/file_missions.py : nouvelle intégration aux missions natives.
agentos/autonomous_runtime.py : insertion de quatre lignes d’initialisation.
L’installateur conserve les autres modifications du runtime et sauvegarde
les fichiers de code remplacés sous backups/V6-Files-1.1-... .
Aucun changement dans les fichiers ou bases de mémoire personnelle.
Au démarrage, l’index documentaire associe les anciens travaux F aux missions M,
et les registres habituels missions.json/tasks.json reçoivent ces missions.
Le ZIP ne contient ni données personnelles, ni fichiers de test, ni projet complet.

TEST RAPIDE
Dans Paul :
Crée un fichier "test_mission_11.txt" contenant Bonjour Romain.

Résultat attendu :
- Paul annonce une mission M-xxx.
- La carte « Création de fichier — test_mission_11.txt » apparaît dans Mission Control.
- La mission passe à Terminée, progression 1/1.
- Son détail indique le chemin du fichier créé.
Utilise un autre nom si ce fichier existe déjà : aucun écrasement automatique.

Pour tester l’autorisation, utilise le chemin réel d’un dossier de test :
Analyse le dossier "C:\Users\romai\Documents\A_trier".
La mission doit apparaître en Approbation. Clique sur Autoriser ou Refuser.

Commandes de consultation (remplacer M-xxx par le numéro réel) :
fichiers resultat M-xxx
fichiers extraits M-xxx
fichiers cherche EDF
fichiers exporter M-xxx
